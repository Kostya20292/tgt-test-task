# Спецификация: «Первые 90» — адаптация новичков

Статус: v1.0 — согласовано

## 1. Проблема

- Компания: опт и розница спорттоваров, ~400 человек (склад, магазины, отдел продаж, офис).
- Приём/увольнение — задачами в Битрикс24.
- 100+ новичков в год, каждый третий из ушедших не доработал до 3 месяцев.
- Вывод: проблема не в найме, а в первых 90 днях. Ранние уходы происходят «тихо» — руководитель и HR узнают о проблеме, когда приходит задача на увольнение.

## 2. Цель продукта

Сделать проблемы новичка видимыми **до** заявления об уходе и подсказать, кому и что сделать сейчас.

Цикл ценности: **сигнал новичка → риск → действие руководителя/HR → отметка результата**.

## 3. Пользователи и роли

| Роль         | Устройство                               | Что получает                                                         |
| ------------ | ---------------------------------------- | -------------------------------------------------------------------- |
| Новичок      | чаще телефон (склад, магазин), иногда ПК | понятный план, контакты, способ сказать «мне плохо»                  |
| Руководитель | ПК / телефон                             | список своих новичков, кому нужно внимание, какие встречи просрочены |
| HR           | ПК                                       | радар всех новичков, входящие задачи Б24, метрики ранних уходов      |

Авторизации нет. Роль выбирается переключателем в шапке (HR / Руководитель + выбор конкретного руководителя). Новичок открывает личную страницу по уникальной ссылке.

## 4. Функциональные требования

### 4.1. Страница новичка (`/n/:token`)

- FR-N1. Приветствие, «День X из 90», текущий этап (Первая неделя / Первый месяц / Испытательный срок).
- FR-N2. Чек-лист адаптации по шаблону подразделения (склад / магазин / продажи / офис) с отметкой выполнения.
- FR-N3. Контакты: руководитель, наставник (если назначен), HR.
- FR-N4. FAQ подразделения (статичный контент: форма, график, зарплата, пропуск, обучение).
- FR-N5. Еженедельный чек-ин (≤ 1 минуты):
  - самочувствие 1–5;
  - «Понимаю, что от меня ждут» да/частично/нет;
  - «Хватает помощи» да/частично/нет;
  - комментарий (необязательно);
  - флаг «Хочу поговорить с HR».
- FR-N6. Если чек-ин за текущую неделю уже пройден — показывается «Спасибо, следующий через N дней».

### 4.2. Кабинет руководителя (`/manager`)

- FR-M1. Список своих новичков, сортировка по риску.
- FR-M2. Карточка новичка: риск и **причины риска текстом**, история чек-инов, прогресс чек-листа, контрольные встречи.
- FR-M2a. Руководитель видит ответы чек-инов, **кроме флага «Хочу поговорить с HR»**: этот флаг и связанная с ним причина риска видны только HR (безопасный канал). Для руководителя такой новичок отображается с баллом риска без раскрытия причины («Есть сигнал для HR»). Комментарий из чек-ина с этим флагом руководителю тоже не показывается: новичок мог написать в нём то, что не хочет обсуждать с руководителем.
- FR-M3. Контрольные встречи: день 1, 7, 30, 60, 90. Статусы: предстоит / сегодня / просрочена / проведена. Отметка «Проведена» + заметка.
- FR-M4. Назначение наставника из сотрудников подразделения.

### 4.3. Радар HR (`/hr`)

- FR-H1. Таблица всех активных новичков: ФИО, подразделение, локация, руководитель, день, риск, причины. Фильтры: подразделение, риск, руководитель. Поиск по ФИО.
- FR-H2. Карточка новичка — как у руководителя + отметка «HR связался».
- FR-H3. Входящие задачи Б24 (мок):
  - «Приём: ФИО, должность, подразделение, руководитель, дата выхода» → «Принять» создаёт новичка и генерирует ссылку;
  - «Увольнение: ФИО, дата, причина» → закрывает адаптацию, новичок попадает в историю;
  - кнопка «Сымитировать новую задачу из Б24».
- FR-H4. Метрики (за 12 мес., по seed-истории):
  - доля ранних уходов (< 90 дней) среди всех уходов;
  - ранние уходы по подразделениям и по неделе ухода;
  - причины ранних уходов;
  - доля новичков, у которых проведены все встречи вовремя.
- FR-H5. Кнопка «Сбросить демо-данные».

## 5. Модель риска (прозрачные правила, без ИИ)

| Сигнал                                                | Баллы |
| ----------------------------------------------------- | ----- |
| Последний чек-ин: самочувствие ≤ 2                    | +3    |
| Флаг «Хочу поговорить с HR» без отметки «HR связался» | +3    |
| «Хватает помощи» = нет                                | +2    |
| «Понимаю, что от меня ждут» = нет                     | +2    |
| Нет чек-ина > 10 дней                                 | +2    |
| Наставник не назначен после 3-го дня                  | +2    |
| Каждая просроченная контрольная встреча               | +2    |
| Чек-лист отстаёт от плана этапа > 30%                 | +1    |

Уровни: 0–1 — зелёный, 2–3 — жёлтый, ≥ 4 — красный. Каждый балл сопровождается человекочитаемой причиной и рекомендуемым действием. Риск вычисляется на лету, чистой функцией.

## 6. Данные

Сущности: `Department`, `Location`, `Employee` (руководители, наставники), `Newcomer`, `ChecklistTemplate`/`ChecklistItem`, `NewcomerChecklistItem`, `Checkpoint`, `CheckIn`, `B24Task`, `Offboarding`.

Seed (вымышленные люди, даты относительно «сегодня»):

- 4 подразделения, ~6 локаций (склад, 3–4 магазина, офис), ~10 руководителей;
- ~25 активных новичков с разными сценариями риска;
- ~120 исторических наймов за 12 мес., ~45 уходов, из них ~1/3 — до 90 дней;
- 3–5 необработанных задач Б24.

## 7. Нефункциональные требования

- NFR-1. Адаптивная вёрстка: корректно от 360px до десктопа; страница новичка — mobile-first.
- NFR-2. Доступность: семантика, клавиатурная навигация, aria-атрибуты, контраст; риск не только цветом, но и текстом.
- NFR-3. Интерфейс на русском.
- NFR-4. Публичный деплой по ссылке.

## 8. Стек

- React + TypeScript + Vite, React Router, SCSS Modules.
- API: Hono в одной Vercel Function (`/api/*`), локально — тот же код на Node.
- БД: Postgres (Neon), ORM Drizzle.
- Тесты: Vitest (модель риска, расчёт этапов/встреч), Playwright (сквозной сценарий).
- Деплой: Vercel.

## 9. Вне объёма (и почему)

- Реальная интеграция с Б24 — нет доступа к порталу; формат задач замокан так, чтобы заменить на вебхук.
- Авторизация — мешает проверяющим, не влияет на суть.
- Уведомления (email/Telegram/Б24) — следующий шаг.
- ИИ-скоринг — нет реальных данных для обучения, правила объяснимее.

## 10. Критерии приёмки (демо-сценарий)

1. HR принимает задачу Б24 «Приём» → появляется новичок со ссылкой.
2. По ссылке новичок проходит чек-ин с самочувствием 2 и флагом «Хочу поговорить с HR».
3. На радаре HR и у руководителя новичок становится красным, причины видны текстом.
4. Руководитель отмечает встречу, HR — «связался» → риск снижается.
5. Метрики показывают долю ранних уходов и разрезы.
6. Все экраны работают на 360px.

## 11. Принятые решения

| Вопрос            | Решение                                                                |
| ----------------- | ---------------------------------------------------------------------- |
| Концепция         | Чек-ины новичка + радар риска для HR/руководителя                      |
| Интерфейс новичка | Адаптивный веб-сайт (ПК и мобильный), без логина, по уникальной ссылке |
| Битрикс24         | Мок входящих задач «Приём»/«Увольнение»                                |
| Фронтенд          | React + TypeScript + Vite + SCSS Modules                               |
| Бэкенд / БД       | Vercel Functions + Neon Postgres + Drizzle                             |
| ИИ                | Не используется, прозрачные правила                                    |
| Роли              | Переключатель ролей, без авторизации                                   |
| Метрики           | Входят в MVP                                                           |
| Защита демо       | Кнопка «Сбросить демо-данные»                                          |
| Приватность       | Флаг «Хочу поговорить с HR» и комментарий к нему видны только HR       |
